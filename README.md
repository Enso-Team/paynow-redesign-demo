# PayNow redesign demo

An unofficial concept redesign of a Singapore bank app's PayNow flow. It isn't affiliated with or endorsed by DBS Bank, POSB or any other bank. No real money moves. PayNow, FAST and the bank are all mocked, and the only people in it are made up.

## The idea

- One Face ID per journey. Log in, Scan & Pay and PayNow each ask once, and Pay never asks again.
- An intent router that goes straight to the destination. Tapping PayNow on the signed-out screen lands on the PayNow menu after Face ID, not on Home.
- Tabs that keep their state. Switching tabs keeps scroll position and loaded data.

[CONTRACTS.md](CONTRACTS.md) has the full technical contract: endpoints, error codes, events, the form bridge and the timing table.

## Layout

| Folder | What it is |
|---|---|
| `services/` | Six Spring Boot 3 services (Java 17, Gradle), with MariaDB and Kafka in docker-compose |
| `web/app/` | pnpm workspace. `apps/web` is the web shell with an in-browser demo backend, `packages/paynow-form` is the React PayNow form that iOS also embeds, `packages/sgqr` parses SGQR codes |
| `ios/` | SwiftUI app generated by XcodeGen from `project.yml`, plus the `Packages/SGQR` Swift package |
| `latency/measured.json` | Per-call network times measured from screen recordings of a real banking app |

## Run the services

You need Docker and a Java 17 JDK.

```sh
cd services
cp .env.example .env              # then replace each placeholder value
scripts/up.sh                     # MariaDB, Kafka and all six services
scripts/e2e.sh                    # curl checks against the running stack
LATENCY_PROFILE=measured scripts/up.sh   # every endpoint waits its time from latency/measured.json
scripts/down.sh                   # stop everything (--wipe also deletes the database)
```

`up.sh` stops with a message if `.env` is missing `JWT_SECRET`, `DB_PASSWORD` or `DB_ROOT_PASSWORD`. A service that's already up keeps its profile, so run `down.sh` before switching to `LATENCY_PROFILE=measured`. See [services/README.md](services/README.md) for ports and test numbers.

## Run the web app

You need Node and pnpm. The e2e scripts drive Google Chrome headless, and `CHROME` overrides its path.

```sh
cd web/app
pnpm install
pnpm dev          # builds the form, then serves http://localhost:5173 against the services
pnpm test         # unit tests in all three packages
pnpm build        # production build in apps/web/dist
pnpm e2e          # journeys against a running build or dev server on 5173 and the services
```

The prebuild step (`apps/web/scripts/copy-assets.mjs`) copies the built form into `apps/web/public/paynow-form/`, which git ignores. Run `pnpm build` or `pnpm dev` from `web/app` so the form gets built first.

For the static demo, with its backend running in the browser and no services:

```sh
pnpm build:demo                     # apps/web/dist-demo, base path /demos/dbs/
pnpm --filter web preview:demo      # http://localhost:4173/demos/dbs/
pnpm e2e:demo                       # in another terminal
```

## Run the iOS app

You need Xcode with an iOS 26 or later SDK, XcodeGen and pnpm.

```sh
cd ios
cp Config/Local.xcconfig.example Config/Local.xcconfig   # optional on the simulator
scripts/sync-form.sh      # builds packages/paynow-form into DBSDigibank/Resources/PaynowForm
xcodegen generate
open DBSDigibank.xcodeproj
```

Build and run the `DBSDigibank` scheme on a simulator. The simulator calls the services on `localhost`, so it needs no `Local.xcconfig`.

On a device, set `DEVELOPMENT_TEAM` and `DBS_BACKEND_HOST_DEVICE` in `Config/Local.xcconfig`. The host is the Mac running the services, as the phone reaches it. The app's ATS settings allow plain HTTP to `localhost` and to `*.ts.net`, so a Tailscale MagicDNS name works as is. Any other host needs its own ATS exception in `project.yml`.

## Record the A/B waterfall

The bar on the entry screen switches the flow (DBS Sequential or Intent Router) and the backend latency (1x or 3x). Run Scan & Pay once in each flow to the Sent screen, then plot both on the canvas:

```sh
ART_DIR=<Assets.xcassets> ios/scripts/install-phone.sh <udid>   # ART_DIR is optional
scripts/verify_flows.py      # both chains from the Mac, with stand-ins for Face ID and the scan
scripts/plot_waterfall.py    # the latest 3x and 1x phone runs (--multiplier picks one)
```

A payee's first payment needs a step-up Face ID, so pay it once before recording.

## Placeholder art

Every image is a plain placeholder: line glyphs, gradients, a grey photo stand-in and a padlock. Swap in your own art under the same file names and similar pixel sizes. The web copies live in `web/app/apps/web/public/img/` and the iOS copies in `ios/DBSDigibank/Resources/Assets.xcassets/<name>.imageset/`.

| Files | Use |
|---|---|
| `entry-bg.jpg` | Background of the signed-out entry screen (1206 x 1791) |
| `entry-login`, `entry-token`, `entry-paynow`, `entry-overseas`, `entry-scan`, `entry-apply` (.png) | White tiles on the entry screen |
| `home-bills`, `home-overseas`, `home-paynow`, `home-security` (.png) | Home shortcuts |
| `pay-bills`, `pay-edp`, `pay-fx`, `pay-local`, `pay-overseas`, `pay-paynow`, `pay-scan`, `pay-scheduled` (.png) | Pay & Transfer shortcuts |
| `tab-home`, `tab-pay`, `tab-apply`, `tab-more`, `tab-wealth` and their `-on` variants (.png) | Tab bar icons. iOS renders them as templates, so keep the transparency |
| `promo-child.jpg` | Promo card photo on the entry screen (1114 x 479) |
| `token-lock.png` | Digital Token padlock (380 x 380) |
| `AppIcon.appiconset/icon.png` | iOS app icon (1024 x 1024, no alpha) |

The sample QR codes in `web/app/packages/sgqr/samples/` (copied to `apps/web/public/samples/`) encode only the seeded test numbers: 91234567, 90000001, 90000002, UEN 201912345K and a made-up NETS code.
